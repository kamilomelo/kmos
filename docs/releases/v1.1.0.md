# KMOS v1.1.0 — existing Arch headless adoption

This release adds a **separate, experimental** adoption path for installed
headless Arch Linux x86_64 systems, including VPSs. It does not convert an
existing KDE desktop. The Arch ISO installer and the KMOS headless → KDE
upgrade remain separate workflows; never run the ISO installer on an installed
system.

## Use

On an installed headless Arch system, clone `main`, review the read-only plan,
then run `./platforms/archlinux/kmos-adopt-headless.sh` from that checkout:

```bash
./platforms/archlinux/kmos-adopt-headless.sh --preflight
./platforms/archlinux/kmos-adopt-headless.sh
```

Have a VPS snapshot or provider console available, and keep working SSH access
while testing. See the [README walkthrough](../../README.md#adopt-an-existing-headless-arch-system-vps)
and the [adoption and account-safety guide](../arch-adopt-headless.md).

## What it does

- Upgrades Arch and installs the headless KMOS CLI packages, including
  OpenSSH if missing. It validates SSH settings, generates missing server host
  keys, enables sshd at boot, and starts it only if inactive. It does not
  rewrite existing SSH settings or change network-manager services.
- Requires a chosen AUR helper and `tododo-bin`. The numbered menu defaults to
  paru; paru is built from source using Rust, while yay is an alternative.
  The helper is system-wide, but system package installation requires sudo.
- Offers local user creation, optional SSH public keys, and guarded account
  removal. `--users-only` handles later account cleanup without reinstalling
  packages. It stages KMOS terminal appearance without overwriting personal
  shell configuration.

## Verification and limits

An initial VPS field run installed the headless packages and verified working
yay and `tododo-bin`. An earlier `paru-bin` failed to load `libalpm.so.15`;
the replacement source build reached its final Rust compile but received
SIGKILL. A memory limit is plausible **but unconfirmed**. The script builds
the source package before offering to remove conflicting binary packages.
The source-build success path and account-removal flow remain **fixture-tested,
not field-verified**. Bash syntax and offline fixtures passed; ShellCheck
0.11.0 was unavailable on the release host.

Pacman transactions may update existing software or run hooks. The script
does not format disks or automatically reboot, back up changed configuration,
or roll back package upgrades or home deletion. Review the plan and confirm
the target account before any destructive account action. `v1.0.0` remains
unchanged.
