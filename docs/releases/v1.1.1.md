# KMOS v1.1.1 — headless adoption sudo fix

This patch release updates the experimental existing-Arch headless/VPS
adoption workflow from [v1.1.0](./v1.1.0.md). It does not change the ISO
installer or convert existing KDE systems.

- New wheel administrators now have sudo authorization checked during creation.
  If needed, the script offers a validated, **per-user** sudoers rule with
  explicit approval; declining stops adoption rather than reporting success.
- The AUR builder uses the same per-user check instead of offering sudo to
  *every* wheel member. `--users-only` can offer repair for existing wheel
  accounts when run from an already authorized administrator or root console.
  A user without sudo cannot grant it to themselves.
- The guided run installs/updates required packages before creating accounts,
  so `sudo` is available for the check. If the script cannot verify access,
  any account already created remains for review; no automatic rollback occurs.

The [README](../../README.md#adopt-an-existing-headless-arch-system-vps) gives
the short start path; the [adoption guide](../arch-adopt-headless.md) has the
package details, safeguards, and paru troubleshooting. Yay worked on an initial
VPS; the source paru build received SIGKILL (OOM unconfirmed). Account cleanup
and the sudo repair have fixture coverage but have not been field-verified.
Bash syntax and offline fixtures passed; ShellCheck 0.11.0 was not available
on the release host. The `v1.1.0` tag remains unchanged.
