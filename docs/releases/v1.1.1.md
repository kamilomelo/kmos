# KMOS v1.1.1 — Arch Linux x86_64

This release documents the `main` installer tested from a normal, unqualified
`git clone` in a fresh isolated Arch x86_64 VM. The install completed, booted
into KDE, and showed the intended transparent login image over black. The
installer's selected `yay` helper and final plan were tested in earlier
isolated x86 VMs. The final VM result was reported by the user, not reproduced
on physical hardware.

## Install and safety

Follow the [README](../../README.md) for the fresh ISO install. Only the
selected **root** partition is always formatted. An existing EFI filesystem
defaults to reuse when eligible; forcing its format requires `EREASE` as well
as the final `FORMAT`. `cfdisk` can write the partition table before either
formatting approval. Review the displayed device identity and plan before
proceeding. For an interrupted KDE stage after the base and bootloader, use
[`resume-kde`](../arch-headless-to-kde.md#resume-a-failed-iso-kde-stage), not a
fresh install on the populated disk.

The installer offers a headless or KDE install and accepts either the displayed
number or name for AUR helper selection. The final disk plan shows the chosen
helper. Standalone [headless → KDE](../arch-headless-to-kde.md) and
[headless Arch adoption](../arch-adopt-headless.md) remain separate, guarded
workflows. Rocky Linux support is unchanged.

## Limits

The new `main` test used virtual Ethernet and a sparse guest disk. A Wi-Fi-only
NetworkManager handoff, KDE recovery from a failed ISO stage, and the new
login appearance on physical hardware still need separate testing. Arch
package upgrades may run hooks; neither the installer nor adoption provides
automatic rollback. Keep snapshots or backups before destructive operations.
